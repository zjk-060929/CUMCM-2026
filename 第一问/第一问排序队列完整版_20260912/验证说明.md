# 验证口径与复现记录

## 为什么分三层检查

算法测试、独立核验和计时分别回答“特殊分支是否按预期处理”“是否与另一套求解过程一致”“当前实现实际要用多长时间”。它们不能互相替代。本包默认求解器不依赖这些离线程序。

## 第一层：52项自动化检查

执行 `python run_checks.py`，结果在 `results/test_results.txt` 和 `results/test_summary.json`。

旧21项回归覆盖测向约束、常规交会、单点线段、卡壳与覆盖，并含100组卡壳枚举和300组测向区域交点枚举对照。新增31项包括：

- 同向上下界保留较严格约束；竖直、水平、斜向反平行矛盾；无平行对也可能产生的空三角形。
- 整个平面、单半平面、竖直/斜向条带、直线、射线和有顶点的无界象限。
- 竖直线段、斜向线段、无平行对的单点以及7个旋转角度下的退化线段。
- 60种输入顺序、150条冗余约束、同向重复边界。
- 包络中间边界删除、401个横坐标的最大函数核验及横坐标只剩单点的交会。
- 1e-6米薄三角形、1e-11量级方向差、微小尺度卡壳、200万米坐标平移。
- 无效输入、零方向、零法向恒真/恒假约束和输出字段。

“52项”指测试方法数量，循环内随机样本未重复计入测试项数。它也不意味着穷尽所有双精度输入。

## 第二层：1500组独立一般半平面

执行 `python validate_independent.py --cases 1500`。默认种子20260912。

每组先随机生成2至14条约束，法向量分量取[-8,8]整数，零法向改为(1,0)，截距取[-25,25]整数。每第三组额外加入[-30,30]方框约束，以得到一部分有界输入。

这个方框是**特定测试输入的四条真实约束**；它不属于主算法，不用于把任意无界输入强行裁成有界区域。其余样本仍可为空或无界。

独立方法：

1. 用SciPy/HiGHS求可行性，变量x、y都没有默认非负界。
2. 可行时分别最小化x、-x、y、-y；任一目标无界则区域无界。
3. 有界时独立枚举两条约束交点，使用2×2线性方程求解，过滤不满足全部原约束的点，再枚举所有可行交点对距离。
4. 与新版的分类和直径比较；直径差大于1e-6米视为失败，保存失败输入。

本次结果：有界217、空集1030、无界253，失败0；直径最大差约1.4210854715202004e-13米。完整摘要在 `results/independent_validation.json`。

这层重点检查一般线性约束。HiGHS同样使用浮点数和自己的容差，且整数生成分布不密集覆盖病态近平行输入；针对这些情况另有第一层专门检查。

## 第三层：三实现计算耗时

执行 `python benchmark.py`，结果在 `results/benchmark.csv` 与 `results/benchmark_summary.json`，可用普通文本编辑器查看CSV。运行时避免同时做独立线性规划等计算。

普通测向档：2、5、10、20、50、100条测向记录，每档4个随机场景。另有20、80、200、400条边界全部有效的正多边形档，每档1个场景。三份实现交替计时，按规模重复3、5或9次，保存中位数和最小值。

普通测向档计入角形约束构造、半平面交、直径、圆覆盖；输入对象构造在计时外。正多边形档从已构造好的半平面对象开始，计入后续求交、直径和覆盖。两组实验的入口不同，分别画图，不横向混合成同一种每次调用耗时。

`legacy_deque`是旧版原代码，其最终逐顶点逐约束检查可能达到二次复杂度；`interval_reference`是前一改进版的逐边界区间法；`sorted_deques`是本次完整实现。所有基准输入都为三份代码可处理的普通有界区域，因此这层计时不能证明旧版处理特殊情况的完整性。

这些时间不包含HTTP通信、文件读写和官方模拟器时间。单次检测稳定读数固定5秒是题目设备设定，与本机几何计算的毫秒耗时分开解释。

## 图件与报告一致性

`generate_figures.py`重算8个算例并保存 `example_results.json`；计时图直接读取当前基准结果。`build_report.py`与Markdown共用 `report_content.py`，从当前测试摘要、独立核验和计时摘要读取统计表。

交付前已将PDF逐页渲染检查文字、公式、图件、页码与排版。单独的9幅图及10个公式也已检查。包内提供所有生成源，方便换机复现；不同机器的计时和字体排版不保证逐字节相同。
